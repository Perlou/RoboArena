# RoboArena 需求文档

> 版本：v0.3（加入大模型应用层） ｜ 日期：2026-11-26 ｜ 配套文档：[ARCHITECTURE.md](./ARCHITECTURE.md)、[PLAN.md](./PLAN.md)
>
> RoboArena 是一个机器人策略评测平台：训练一个神经仿真器（动作条件的世界模型），
> 在里面批量评估机器人策略，并检验这种评估和真实仿真器里的结果是否一致。
> 它是「世界模型」课程 Phase 12 的结业项目，作为独立仓库开发。
>
> v0.3 起，平台之上加一层大模型应用：用自然语言操作平台的 Agent、模型网关、AI 评测、领域小模型（第 1.5 节）。

## 1. 背景

### 1.1 行业问题

机器人策略（行为克隆、Diffusion Policy、VLA）的评估是具身智能里最贵的环节：
每评一次都要在真机上跑几十到几百个回合，慢、要人值守、环境难以复原，不同实验室之间的结果也难以比较。
策略迭代的速度因此被评估的速度卡住。

一个思路是把世界模型当仿真器：从机器人数据里学一个「给定当前画面和动作，生成下一帧画面」的模型，
让策略在这个模型里跑，用模型里的成功率代替真机成功率。这是 2024–2026 年的活跃方向
（Li et al. 2024，SIMPLER，arXiv:2405.05941；Quevedo et al. 2025，WorldGym，arXiv:2506.00613；
Li et al. 2025，WorldEval，arXiv:2505.19017）。

这个思路能不能用，取决于一个可以量化的问题：**模型里排出的策略名次，和真实环境里的名次一致吗？**
绝对成功率可以有偏差，只要名次对，就能用来筛选策略、做回归测试。

### 1.2 本项目做什么

在一个受控的任务（PushT 推块）上把这条链路完整做出来，并回答上面的问题。
PushT 有真实的物理仿真器，所以「真值」是可以精确得到的，这是能够检验神经仿真器的前提。

项目同时是一个工程作品：数据管线、训练、评测、服务、看板、遥操作都按可交付的标准做。

### 1.3 用户

| 角色 | 想做什么 |
| --- | --- |
| 策略研发者 | 提交一个策略检查点，拿到它在评测集上的成功率和在排行榜上的位置，不用自己搭评估环境 |
| 仿真器研发者 | 训练一个新的世界模型，知道它作为评估器「能信多远」：排序一致性、可信视野、推理延迟 |
| 演示的观众 | 在浏览器里用鼠标操纵神经仿真器里的推杆，直观看到世界模型在生成什么、哪里会出错 |
| 用自然语言操作平台的人（v0.3） | 不记命令和配置项，直接问「现在哪个策略最好、区间多宽」「再评一遍某个策略」「用 50 条演示训练一个」，得到有出处的回答 |

本项目里这几个角色都是作者本人，但功能按角色划分，接口按「别人也能用」设计。

### 1.4 关于名字

2025 年有一篇同名工作（RoboArena，真机分布式策略评测基准，arXiv 编号待核对）。
本项目与它无关，方向相近但做法不同（它用真机众包评估，本项目用神经仿真器）。
如果将来公开发布，需要考虑改名或加副标题以免混淆。

### 1.5 大模型应用层（v0.3）

仿真与评测平台的使用门槛在命令、配置项和对结果的解读上。让大模型来操作平台，是数字孪生与具身仿真里常见的一类应用：
自然语言交互、任务分解、参数生成。这一层同样有一个可以量化的问题：**它给出的操作和数字靠得住吗？**

本项目对这一层的做法与对神经仿真器的做法相同：先建评测，再谈能力。平台自己就是真值的来源
（排行榜、运行记录都能由函数现算），所以 Agent 答得对不对、有没有编数字，可以用程序判定，不靠人打分。

范围：模型网关、AI 评测、Agent、把「指令 → 工具调用」做进一个小参数模型（数据构建、微调、评测、量化、本机部署）。

## 2. 目标与非目标

### 2.1 研究问题

| 编号 | 问题 | 回答方式 |
| --- | --- | --- |
| RQ1 | 在神经仿真器里评估得到的策略排序，和真实仿真器里的排序一致吗？ | 秩相关及其置信区间、MMRV |
| RQ2 | 一致性随回合长度怎么变化？神经仿真器的预测能信多少步？ | 开环误差曲线、可信视野、按回合长度截断后的秩相关 |
| RQ3 | 仿真器本身的质量（训练预算、上下文长度）对排序一致性的影响有多大？ | 预注册的消融 |
| RQ4 | 本机可部署的开源模型做这个平台的 Agent，任务完成率、幻觉率、延迟各是多少？结果校验能把幻觉率降多少？ | 固定工作区上的 AI 评测，真值由平台函数现算 |
| RQ5 | 把「指令 → 工具调用」微调进约 1.5B 参数的模型，相对「大模型 + 提示词」和「小模型 + 少样本提示」，效果、延迟、成本如何？量化损失多少？ | 同一套用例上五种配置的配对比较 |

### 2.2 工程目标

- G1：一条命令从配置文件复现完整结果（数据 → 策略 → 仿真器 → 评测 → 报告）。
- G2：每一个报告里的数字都能追溯到一次运行记录（配置、代码版本、数据指纹、随机种子）。
- G3：评测能力以服务的形式提供（HTTP 接口 + 任务队列），不只是脚本。
- G4：有一个浏览器看板展示结果，一个遥操作页面可以实时操纵神经仿真器。
- G6：服务具备上线所需的基本面：访问控制、可观测性、持续集成。
- G7：任务可扩展：接入第二个任务时只新增一个任务插件，不改评测、服务、前端。
- G5：标准规模的全流程在一台 M1 Max（32 GB，无 NVIDIA GPU）上能跑完。
- G8：能用自然语言操作平台；回答里的数字都有出处，改动工作区的操作受权限约束。
- G9：大模型应用有自己的评测体系：任务完成率、工具调用正确率、幻觉率、延迟、成本，逐用例入库、带置信区间。
- G10：一个领域小模型走完数据构建、微调、评测、量化、本机部署的全过程，并接回 Agent 做对比。

### 2.3 明确不做

| 不做 | 原因 |
| --- | --- |
| 真机 | 工时无法估计；仿真里统计扎实的结果先于真机演示 |
| 第二个任务、语言条件、VLA | 单任务上先把评估方法做扎实。任务以插件形式抽象（FR-T），本期只实现 PushT |
| RAG 知识库、多模态场景理解 | 本期应用层只做 Agent 与领域小模型；这两项各自需要一套评测，留作后续 |
| 多 Agent 协作、图式工作流 | 平台的操作只有十来个，单个 Agent 的工具循环够用；多 Agent 会让失败难以归因 |
| 通用问答能力的微调 | 小模型只学「指令 → 工具调用」：输出可以逐字段判对错 |
| 多租户、账号注册、单点登录 | 访问控制只做到 API 令牌与两种角色（FR-A），够把服务安全地暴露到本机以外 |
| 自动部署 | 持续集成做到构建镜像为止（FR-C）；发布由人手动触发 |
| 分布式训练、多机调度 | 规模不需要 |
| 在神经仿真器里训练策略 | 那是另一个题目（世界模型当数据引擎 / 想象训练） |
| 追求最强的世界模型 | 目标是检验评估方法，模型够用即可；仿真器质量本身是被研究的变量（RQ3） |

## 3. 任务与数据的既定事实

以下数字已在本机核对（`gym-pusht` 0.1.8 的源码与缓存的演示数据）：

| 项 | 值 |
| --- | --- |
| 环境 | `gym_pusht/PushT-v0` |
| 观测 | 96×96 RGB 画面；另有推杆位置（2 维） |
| 动作 | 推杆的目标位置，2 维，像素坐标 0–512 |
| 控制频率 | 10 赫兹 |
| 回合上限 | 300 步 |
| 成功判定 | T 形块与目标区域的重叠比例 `coverage` 大于 0.95 |
| 奖励 | `clip(coverage / 0.95, 0, 1)` |
| 可设定初始状态 | 支持，`reset(options={"reset_to_state": [推杆 x, 推杆 y, 块 x, 块 y, 块朝向]})` |
| 人类演示 | `lerobot/pusht`：206 个回合，25650 帧，回合长度 49–246 步（平均约 125 步） |
| 演示里没有的 | T 形块的位姿、回合的初始状态、成功的画面（见下） |

最后一行有两个后果：演示数据不能在仿真器里按状态重放；需要位姿标签的数据必须自己在仿真器里采集。

M1 实测补充的两条事实：

- 演示里带有奖励，可以由它还原出 `coverage`（与用画面像素重叠面积做的独立估计相关系数 0.996）。
- 206 条演示里**没有一帧被标为成功**，记录到的 `coverage` 最大为 0.90，原因没有查明。
  所以「成功附近长什么样」的数据只能来自策略自己的回合（FR-D2 的第三种来源，要等 M2 有了策略才能采）。

M2 实测补充：

- 成功的画面在策略自己的回合里有了：17 个策略各跑 16 个回合，272 个回合里 34 个成功，成功帧 202（占 0.26%）。
- 成功常常只有一帧：34 个成功回合里 14 个只有 1 帧被判为成功，`coverage` 在阈值附近徘徊。
- 仿真器给出的块朝向是累计转角，不在 (−π, π] 内（实测范围 −11.9 到 7.4）。

## 4. 功能需求

优先级：**P0** 必须交付；**P1** 应该交付；**P2** 时间允许再做。

### 4.1 数据（FR-D）

| 编号 | 需求 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| FR-D1 | 下载并解码 PushT 人类演示，转成统一的回合文件格式 | 回合数、总帧数与上表一致；重复运行不重新下载 | P0 |
| FR-D2 | 在仿真器里采集带真值标签的回合：演示动作加噪回放、随机游走、已训练策略的回合 | 每个回合带逐帧的块位姿、`coverage`、成功标志和初始状态；采集过程由种子完全确定 | P0 |
| FR-D3 | 数据校验 | 形状、数值范围、动作与观测的对齐、回合边界各有一条自动检查；故意破坏数据后检查能报错 | P0 |
| FR-D4 | 按回合切分训练 / 验证 / 测试 | 同一回合的帧不会出现在两个子集；切分由种子确定 | P0 |
| FR-D5 | 数据集指纹 | 内容不变则指纹不变；改动任意一帧则指纹改变；指纹写入使用该数据集的每次运行 | P0 |
| FR-D6 | 固定的评测集：一组初始状态 | 评测集有自己的标识与指纹；与训练数据的初始状态不重合 | P0 |

### 4.2 策略库（FR-P）

| 编号 | 需求 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| FR-P1 | 统一的策略接口：输入最近几帧画面，输出一段动作（动作分块） | 同一个策略对象不加改动即可接入真实仿真器和神经仿真器 | P0 |
| FR-P2 | 行为克隆策略 | 真实仿真器里的成功率明显高于随机策略 | P0 |
| FR-P3 | Diffusion Policy（小型） | 能训练、能评估；成功率如实报告 | P1 |
| FR-P4 | 一组水平拉开的策略（目标 10–12 个）：不同演示条数、训练步数、执行噪声，加上随机策略 | 真实成功率覆盖从接近 0 到本项目能达到的最高水平；相邻策略的区间不必都分开 | P0 |
| FR-P5 | 外部策略接入：实现接口并注册即可参加评测 | 文档里有一个最小示例，测试里有一个假策略走完全流程 | P1 |

### 4.3 神经仿真器（FR-W）

| 编号 | 需求 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| FR-W1 | 动作条件的世界模型：给定历史画面与动作，生成下一帧，可自回归展开 | 一步预测的误差低于「复制上一帧」这个基线 | P0 |
| FR-W2 | 成功判定：从模型的内部状态读出 `coverage`（及块位姿） | 在真实画面的验证集上，读出的 `coverage` 与真值的误差有报告；据此判定的成功与真值的一致率有报告 | P0 |
| FR-W3 | 批量并行展开：多个回合同时推进 | 批量与逐个展开的结果一致（同种子下数值相等到浮点误差） | P0 |
| FR-W4 | 与真实仿真器相同的接口 | 评测器的代码里不出现针对某一种仿真器的分支 | P0 |
| FR-W5 | 可替换的模型后端；第二个后端（扩散模型，少步采样） | 新后端只实现世界模型接口，评测、服务、前端不改 | P2 |

### 4.4 评测（FR-E）

| 编号 | 需求 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| FR-E1 | 在指定仿真器、指定评测集上评估指定策略 | 输出逐回合记录：是否成功、最大 `coverage`、步数、种子 | P0 |
| FR-E2 | 成功率及其置信区间 | 用 Wilson 区间；对手算例子的测试通过 | P0 |
| FR-E3 | 排序一致性：Spearman 秩相关 + bootstrap 区间；MMRV；成功率估计的偏差与平均绝对误差 | 各统计量对手算例子的测试通过；区间的重采样单位写明 | P0 |
| FR-E4 | 世界模型诊断：开环误差随步数的曲线、可信视野 | 「复制上一帧」基线画在同一张图上；可信视野的定义写在报告里 | P0 |
| FR-E5 | 一致性随回合长度的变化 | 把回合截断到不同长度后分别计算秩相关 | P1 |
| FR-E6 | 评测结果入库，可重复查询 | 同一（策略、仿真器、评测集、种子）重复评测不产生重复记录，或明确标为新的一次 | P0 |
| FR-E7 | 报告生成：结果表与图 | 一条命令从结果库生成；图表里的数字与库里的一致 | P0 |
| FR-E8 | 预注册的消融：仿真器训练预算、上下文帧数、成功判定方式 | 每组消融的预期方向在跑之前写进计划；结果无论是否符合预期都报告 | P1 |

### 4.5 实验管理（FR-M）

| 编号 | 需求 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| FR-M1 | 配置文件驱动，命令行可覆盖单项 | 运行目录里保存生效的完整配置；用它能重新发起同样的运行 | P0 |
| FR-M2 | 运行记录：配置、代码版本、数据指纹、种子、指标曲线、起止时间、状态 | 工作区有未提交改动时记录里有标记 | P0 |
| FR-M3 | 断点续训 | 中断后续训与不中断训练，同种子下损失曲线一致（CPU 上数值相等；MPS 上允许的偏差写明） | P0 |
| FR-M4 | 模型与策略注册表 | 每个条目有名称、类型、检查点的内容哈希、来源运行；检查点被改动后加载时能发现 | P0 |
| FR-M5 | 预设规模：冒烟、本机、云端 | 冒烟配置全流程在数分钟内跑完，用于测试与持续集成 | P0 |

### 4.6 服务（FR-S）

| 编号 | 需求 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| FR-S1 | 查询接口：策略、仿真器、评测集、运行记录、排行榜、一致性结果 | 接口有自动生成的文档；有接口测试 | P0 |

| FR-S5 | 容器镜像 | 镜像内能启动服务并通过健康检查（CPU 推理） | P1 |

### 4.7 前端（FR-U）

技术栈：React + Vite + TypeScript，构建产物由后端服务托管。

v0.3 起整组降为 P2（应用层优先）；下表的优先级是组内的相对次序。

| 编号 | 需求 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| FR-U1 | 排行榜页：各策略在两种仿真器里的成功率与区间 | 数据来自接口，不写死在页面里 | P0 |
| FR-U2 | 一致性页：真实成功率对神经仿真器成功率的散点图、秩相关与区间、开环误差曲线 | 同上 | P0 |
| FR-U3 | 遥操作页：鼠标控制推杆，实时显示神经仿真器的画面 | 显示实测帧率与每帧延迟；可重置、可切换仿真器 | P0 |
| FR-U4 | 并排对照：同一串动作下真实仿真器与神经仿真器的画面并排显示 | 能直观看到两者从哪一步开始分叉 | P1 |
| FR-U5 | 回合回放：查看某次评测里某个回合在两种仿真器里的录像 | 从排行榜能点进去 | P2 |
| FR-U6 | 从页面提交评测任务 | 能看到任务进度 | P2 |
| FR-U7 | 接口类型由后端的 OpenAPI 描述生成 | 前端没有手写的接口类型；后端接口改了而前端没跟上时，类型检查会失败 | P0 |
| FR-U8 | 前端测试 | 数据变换与关键组件有单元测试；`tsc --strict` 通过 | P1 |
| FR-U9 | 令牌输入：服务要求鉴权时，页面能填入并保存令牌 | 未带令牌时给出明确提示，不是空白页 | P1 |

定为 P0，因为它决定核心接口的形状，事后再改代价最大。

| 编号 | 需求 | 验收标准 | 优先级 |

## 6. 基线与指标

### 6.1 基线

| 对象 | 基线 | 作用 |
| --- | --- | --- |
| 世界模型的预测 | 复制上一帧 | 模型至少要比「什么都不预测」好 |
| 策略 | 随机动作 | 策略库的下界 |
| 排序一致性 | 随机排序（秩相关的期望为 0） | 一致性的下界 |
| 排序一致性 | 用训练不足的仿真器做同样的评估 | 说明一致性来自仿真器的质量，不是偶然 |
| 成功率真值 | 真实仿真器 | 一切比较的参照 |
| Agent 的回答 | 平台函数在固定工作区上现算的结果 | 判定回答对错的参照 |
| 微调后的小模型 | 同一个小模型的零样本与少样本提示；大模型零样本 | 微调要赢的是少样本提示，不只是零样本 |

### 6.2 指标

| 指标 | 定义 | 用于 |
| --- | --- | --- |
| 成功率 | 回合内 `coverage` 曾超过 0.95 的比例，配 Wilson 区间 | 每个（策略，仿真器）组合 |
| Spearman 秩相关 | 两种仿真器下策略成功率的名次之间的相关系数 | RQ1 主指标 |
| MMRV | 平均最大排序违例（Mean Maximum Rank Violation），出自 SIMPLER：名次排反的策略对里，真实成功率差得越多罚得越重 | RQ1 辅助指标 |
| 成功率偏差、平均绝对误差 | 神经仿真器成功率减真实成功率的均值、绝对值的均值 | 判断绝对数值能不能用 |
| 开环误差曲线 | 从真实起点出发，喂真实动作序列，第 $k$ 步预测与真实的差距 | RQ2 |
| 可信视野 | 开环误差首次超过某个阈值的步数；阈值的取法在计划里预先写定 | RQ2 |
| 判定头误差 | 在真实画面上读出的 `coverage` 与真值之差 | 把「模型预测错」和「判定错」分开 |
| 单步延迟 | 各环节耗时的中位数与 95 分位数 | NFR-2 |
| 工具调用完全匹配率、合法率 | 模型给出的工具名与全部参数和标准答案一致的比例；输出能解析且通过参数校验的比例 | RQ4、RQ5 |
| 任务完成率 | 多步用例里，最终回答的事实与工作区的最终状态都通过检查的比例 | RQ4 |
| 幻觉率 | 回答里出现、却不在本次工具输出或用户输入里的数字所占的比例；按回答、按数字各报一个 | RQ4 |
| 越权次数 | 未经确认就执行了需确认操作的次数 | RQ4 |
| 模型调用的延迟与用量 | 每次调用的耗时（不含命中缓存的）、输入与输出的 token 数、估算成本 | RQ4、RQ5 |

### 6.3 一个需要事先说清的统计限制

策略只有十来个时，秩相关的置信区间会很宽。这是这类评估固有的问题，不是实现缺陷。
处理方式：报告区间而不是只报点估计；同时报告 MMRV 和散点图；在报告里写明策略个数。

## 8. 风险

| 风险 | 可能性 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 小模型在本机训练不出像样的行为克隆策略，策略水平拉不开 | 中 | 高 | 见止损条件第一行；必要时把策略训练放到 4090 |
| 自回归漂移：展开几十步后画面失真，长回合不可信 | 高 | 高 | 训练时用多步展开损失；训练数据包含差策略到达的状态；片段评估作为后备 |
| 神经仿真器只见过专家数据，对差策略的行为预测得过于乐观 | 高 | 中 | 数据里加入加噪回放、随机游走和策略自身的回合（FR-D2） |

| 判定头的误差被误读成世界模型的误差 | 中 | 中 | 判定头单独在真实画面上评估（FR-W2） |
| 前端与服务挤占实验时间 | 高 | 中 | 里程碑顺序的硬约束；前端只做三个页面，接口类型自动生成，不做设计系统 |
